## 2. Prioridad ALTA

### [x] A1. `POST /api/decks/my/<id>/entries/`: HTTP 500 y se salta la validación del mazo
**Archivo:** [backend/decks/views.py:172](../backend/decks/views.py:172) (`deck_entry_view`)

| Body enviado | Respuesta |
|---|---|
| `{"card_id": 11578, "quantity": -5}` | **500** `IntegrityError` |
| `{"card_id": 11578, "quantity": "abc"}` | **500** `ValueError` |
| `{"card_id": 99999999, "quantity": 1}` | **500** `IntegrityError` |
| `{"card_id": "xyz", "quantity": 1}` | **500** |
| `{"card_id": 11578, "quantity": 60}` | **200**: el mazo quedó con 60 copias de *Daga Ritual* |

**Causa:**
- `quantity` y `card_id` se usan directo, sin validar tipo, rango ni existencia.
- No se aplican las reglas de 2.2: máx. 3 copias, 50 cartas y banlist.
- Además ignora `is_sideboard`.

**Cambio:**
- Si la UI no usa este endpoint (según las notas de 2.2), **eliminarlo** de `decks/urls.py`.
- Si se mantiene, validar con un serializer (`card` como `PrimaryKeyRelatedField`, `quantity` como `IntegerField(min_value=1)`) y reutilizar las reglas de `DeckCreateSerializer.validate` sobre el mazo resultante antes de guardar.

**Aceptación:** los 5 casos de la tabla responden 400 (o 404 si se elimina) y nunca 500.
**Test:** agregar los 5 casos a `backend/decks/tests_rule_gap.py`.

### [x] A3. `/decks` en móvil: el botón "Buscar" queda fuera de la pantalla
**Medido a 375 px:** el botón va de 338 a 407 px; el viewport termina en 375.

**Causa:** en [deck-list.component.scss:84](../frontend/src/app/pages/deck-list/deck-list.component.scss:84) el `input` tiene `flex: 1` pero no `min-width: 0`. En móvil la regla global anti-zoom de iOS (`font-size: 16px`) aumenta su ancho mínimo intrínseco y empuja el botón hacia afuera.

**Cambio:**
```scss
.search-bar input { flex: 1; min-width: 0; }
```
**Extra:** buscar el mismo patrón en otros buscadores con botón al lado:
```bash
grep -rn "flex: 1;" frontend/src/app --include=*.scss | grep -i -B2 "input"
```
**Aceptación:** a 320 y 375 px el botón "Buscar" se ve completo.

### [ ] A4. Datos: el 80 % de las cartas MyL tiene el nombre en minúsculas y sin tildes
**Medido en la BD local:** 1935 de 2427 cartas. **En producción pasa lo mismo** (se verificó con un GET público a `iterva.pythonanywhere.com/api/cards/`).

| Edición | Cartas afectadas |
|---|---|
| IMP - Bestiarium | 393 |
| IMP - Onyria | 385 |
| Espíritu Samurái | 338 |
| IMP - Kaiju vs Mecha - Titanes | 292 |
| IMP - Libertadores | 257 |
| Ángeles y Demonios: Vigilantes | 71 |

**Ejemplos:** "transformacion", "capitan daisuke", "perder la razon", "espada de ohiggins", "abrazo de maipu", "nu-galahad el bastion".

**Más grave aún:** en producción, buscar `transformacion` devuelve a la vez "transformacion" y "Transformación". Hay 435 pares nombre + edición repetidos en la BD local (parte pueden ser variantes de arte; revisar).

**Impacto:** se ve descuidado en el catálogo, el constructor, la vista de mazo y la imagen exportada. Además la agrupación por nombre de `getEffectiveMaxCopies()` puede fallar si "Transformación" y "transformacion" no normalizan igual.

**Cambio:**
1. Management command `fix_card_names` que tome el nombre bien escrito desde la fuente original (el mapping JSON de ImageKit/Cloudinary, o el `name` de la variante con mayúscula que ya existe). Debe tener `--dry-run` y generar un CSV con los cambios para revisarlo a mano.
2. Revisar los duplicados reales (misma carta, misma edición) y fusionarlos, reapuntando `DeckEntry` y la colección, como ya lo hace el comando de `Shadow Ban`.

**Aceptación:** `Card.objects.filter(name__regex=r'^[a-záéíóúñ]').count()` baja a ≈ 0 y ninguna búsqueda devuelve duplicados solo por mayúsculas o tildes.
